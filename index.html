Project overview

Porting gh extension to the flox CLI

A working Rust implementation of a GitHub-CLI-style extension system for flox, plus the design document it came from and three reference extensions that exercise every install path. This is a map of all three.

The one-paragraph version. Flox users had no first-class way to add commands to the flox CLI. gh solved the same problem in 2021 with a small, opinionated package manager for gh-<name> repos. This project ports that model — install, list, remove, upgrade, search, and dispatch of flox <name> to a flox-<name> executable — and adds the one thing gh has no concept of: an extension can declare which flox environment it runs inside.

What shipped versus what was designed

The implementation tracks the design document closely on architecture and diverges from it in several concrete places — some improvements, some drift, one documentation error. Because those divergences are scattered across three artifacts, they are collected in two places rather than narrated inline:

  • Manifest and schema differences live on the manifest page, where the field-by-field reference sits next to a drift table.
  • The exact file-by-file footprint — 33 files, and which ten already existed — is on the change inventory.
  • Behavioral and structural differences, plus everything that could bite a maintainer, live on the risks page.

Public repository links and install commands for the three reference extensions are collected on the examples page.

The headline: the shipped flox-extension.toml schema is not the one in the design document, the dispatch mechanism is better than the one designed, and the author guide describes a placeholder substitution that the code does not perform.
