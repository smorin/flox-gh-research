DemonstratesRelease-asset resolution, the [extension.binary] manifest stanza, archive extraction, and a tag-triggered matrix build

Will not install on Linux. v0.1.0 ships macOS assets only, so on Linux the installer correctly reports no release asset matches. This is scoped, not forgotten — the repo's own PROJECTS.md tracks Linux as P02, and puts Windows out of scope because flox's platform matrix does not include it.

flox-hello-local

smorin/flox-hello-local

Canonical local-authoring reference · installs as hello-local

Clonegit clone https://github.com/smorin/flox-hello-local.git
Installcd flox-hello-local && flox extension install --from-path .
Runflox hello-local world
State2 commits · tagged v0.1.0 · CI workflow only
DemonstratesThe --from-path dev loop with GitHub out of the picture at install time

The only one of the three whose install command does not name the repository. You clone it by hand, then point flox at the working tree — which is the whole point.

A fourth repo that does not exist

The author guide links a fourth example, flox-examples/flox-hello-pinned, described as demonstrating mode = "pinned" and [on_active] inside = "error". No such repository was published.

It matters more than a broken link usually would, because pinned mode is the one genuinely novel feature in the whole system — the piece with no gh equivalent — and it is the only mode with no working example to copy. Anyone wanting to see it in practice has to read the bats tests.

Two related inconsistencies in the same docs, worth knowing before you follow a link from them: the user guide's quick tour installs from flox-examples/flox-hello-script, and the author guide links smorin/flox-hello-script. The repos live under smorin; the flox-examples references are left over from the design document's original plan and will not resolve. Catalogued with the rest on the risks page.
